# M1 core source emission

`examples/Counter.asy` compiles the bounded counter against the committed
reference at `850aa68`. The runtime is 326 bytes and creation is 357 bytes.
The source emits the same ABI and layout JSON as `reference/counter/`.
Its behavior matches the reference on all 30 frozen calldata/prestate
cases, under both geth execution paths. The generated bytes differ from
the 177-byte hand-assembled runtime because the generic lowering uses
explicit blocks and memory snapshots.

```
_build/default/bin/assay.exe emit examples/Counter.asy -o Counter-out
_build/default/bin/assay.exe diff examples/Counter.asy --calldata 0x6d4ce63c
```

This slice uses the carried grammar. It adds no kernel former and changes
no file under `lib/` or `surface/`. The subsequent [contract surface](M1-SURFACE.md)
adds bounded `contract`, `storage`, `entry` and `do` sugar. Proof-producing
guards and the M1 performance threshold remain open. The
[source model](M1-RUN.md) adds public `run`, and the
[source proofs](M1-PROOFS.md) establish overflow freedom for its Lean model.
These tests are not a proof of the
OCaml compiler. The two executors are geth entry points, not independent
client implementations.

## Checked core protocol

The compiler selects the backend by name. A source that defines a global
named `Entry` goes to the M1 backend, and every other source goes to the
M0 backend. An M0 source must therefore not use the name `Entry` for an
unrelated global, because the M1 schema check refuses it.

The source declares the unchanged M0 `Word`, `Eff` and `EvmOpcodes`
protocol, plus `ResultWord` and `Tx` from `emit/recognize.ml`. The compiler
compares checked declarations and family tables with its canonical
schema. Renaming an opcode constructor or changing its type is refused.
The names are backend conventions, not trusted evidence by themselves.

`Storage` is a `prod` of named aliases of `Word 256`. Each alias names a
layout field. `storage : Storage` contains consecutive slot numbers from
zero, as in M0. The current emitter requires a nonempty storage record;
the collection recognizer limits it to 32 fields. Closures and tail calls
in storage are refused before specialization. Slots occupy whole words,
with no packing or dynamic addressing.

`Entry` is a nonempty `sum` of named argument-record types. Each record
is a `prod` of named `Word 256` aliases. A record name becomes a function
name, and its field aliases become ABI argument names. Empty argument
records describe zero-argument functions. The recognizer permits at most
32 entries and 32 arguments per entry, and rejects duplicate names within
a collection. This explicit naming protocol precedes surface sugar.
When every argument record is empty, at least one must use the explicit
form `def get : Type 0 := (prod () : Type 0)`. The annotation keeps the
entry sum in `Type 0` while its empty payload erases. A table of only bare
`prod ()` records receives a named backend refusal. Mixed tables keep
their existing form. The [nullary contract](M1-NULLARY.md) documents the
accepted schema and its validation.

The selected export must have an explicit `Entry -> Tx` type. The emitter
specializes it once for each checked variant leg, injecting symbolic
argument words. The same entry rows supply the ABI printer and dispatcher.
Selectors come from in-tree Keccak over the derived canonical signature;
selector collisions are refused before file creation. A `view` annotation
is inferred only when neither branch of any operation can store. Every
other entry is nonpayable. Every successful runtime return is one word.

One decoder rule applies to every entry: require four selector bytes plus
32 bytes per argument, decode each full uint256, and ignore trailing
bytes. Unknown selectors and short heads revert with empty data. A common
CALLVALUE guard rejects value before dispatch, including fallback calls.

## Runtime effects

| Constructor | Behavior |
| --- | --- |
| `done value` | Return one ABI word |
| `store slot value next` | Store a word and continue |
| `load slot continuation` | Snapshot a slot into a word and specialize the continuation |
| `add a b continuation` | Deliver a success word or overflow error to the continuation |
| `sub a b continuation` | Deliver a success word or underflow error to the continuation |
| `le a b yes no` | Choose `yes` exactly when `a <= b` |
| `abort` | Revert with empty data and roll back writes |

The [typed error protocol](M1-ERRORS.md) optionally adds an `Error` sum
and `reject : Error -> Tx`, with ABI-encoded revert payloads. Existing
core programs without `Error` keep the protocol above.

`ResultWord` is the existing collection sum of `Word 256` and unit. The
success leg contains the arithmetic result. The error leg contains no
word. The source can revert or recover from an error; a recovered error
does not automatically roll back earlier writes. Both legs are compiled,
and the kernel checks eliminations. A failed arithmetic operation cannot
expose its wrapped machine value to the source continuation.

Continuation closures exist only during compilation. Exact-arity known
applications specialize their captured values, including symbolic words.
No closure, Word box or general-purpose heap value reaches the assembler.
Each load and successful arithmetic result has its own memory word. A
later write therefore cannot change an earlier load's value. Storage slots
must stay compile-time constants within the declared layout. Unboxing a
symbolic Word into Nat is refused with `NAT_REFUSE`.

M0 compile-time Nat arithmetic retains its 4096-bit bound. Both modes share
the 100,000-step specialization budget. M1 additionally bounds transaction
depth at 128, temporary allocation at 1024 words and runtime at 24,576
bytes. All budget failures are named refusals before output creation.

`constructor : Eff` is a closed sequence of M0 puts ending in `ret zero`.
It initializes storage, then copies and returns the generated runtime.
A constructor read or a nonzero return value is refused. Creation has its
own CALLVALUE guard. The emitted prefix computes its own byte offset.

## Validation

`python3 -P dev/m1-emit-test.py` checks source emission, the 30 reference
cases, ABI/layout equality, three-way disassembly and both creation
outcomes. All 216 emitted runtime instructions are exercised. The eight
additional live programs cover two arguments, ignored trailing bytes,
short heads, arithmetic recovery, load snapshots, inferred view status
and a valid zero selector. Eleven checked but unsupported sources must
fail before creating output, including a selector collision independently
checked by both in-tree Keccak and cast.
Alternate and absent export names are checked separately.

Eight compiler mutations cover nonpayable dispatch, overflow, bounds,
subtraction, calldata length, constructor value, ABI mutability and the
protocol family check. Each must fail its named witness, then its restored
control must pass. Raw captures and five-file hashes are retained under
`.gatework/m1-emission/`.

`dev/gates.sh` includes this as an M1 leg. The `M0-VALIDATION` stamp still
depends only on M0 legs, and the final M0 exit stamp still requires user
ratification. M1 core differential evidence does not imply completion of
the full M1 milestone.
