# M2 ABI goldens and negative witnesses

M2 group 7 checks the complete source ERC20 ABI against the frozen reference
and adds direct Lean rejection controls. Run `python3 -P dev/m2-abi-test.py`
after `make`. `make test` includes this gate, and `dev/gates.sh` and
`make gates` select the cumulative `--m2-reconcile` schedule, which
includes the `--m2-abi` legs.

## Golden provenance and equality

The golden is [`reference/erc20/abi.json`](../reference/erc20/abi.json),
introduced with the hand-assembled ERC20 reference. Its
[provenance](../reference/erc20/README.md) identifies the manually authored
ERC20 interface. It is not generated by Assay or solc. This group leaves
the golden and its manifest unchanged. Its SHA-256 is
`7715636c0342b68c68f6b93c1daf97e35d901770d2a7086055607bff8c31d3df`.
The gate pins that digest independently and checks the manifest agrees.

The live compiler checks and emits `examples/ERC20.asy`. The emitted ABI
must equal the golden under actual `jq -S -c` normalization. All twelve
declarations participate: the constructor, nine functions and two events.
Before `jq` runs, a strict Python parse rejects any object that repeats a
key, because `jq` keeps only the last value of a repeated key. After that
check, only object key order and whitespace are normalized. Declaration
and parameter array order, names, types, mutability, event indexing and
anonymous flags remain binding.

One positive control reverses every object's key order and changes
indentation. Fifteen altered schemas must differ: missing and extra
functions, declaration order, function name, input name, input type,
input order, output type, output name, mapping mutability, write
mutability, constructor payability, event indexing, anonymous events
and a missing event. A sixteenth control puts a conflicting
`"stateMutability": "nonpayable"` key ahead of the `view` key of
`balanceOf`. The gate proves that `jq -S -c` alone makes this file equal
to the golden, and that the strict parse rejects it.

## Mapping mutability repair

The first comparison exposed `balanceOf` and `allowance` being emitted as
`nonpayable`. Mapping-key setup uses temporary stores in the intermediate
program, which the old classifier treated as persistent writes.
`Emit.Mapping.readonly` now consults the mapping cells. A key store
continues into the following transaction; scalar, mapping-value,
reserved and unknown stores are conservatively writes. Both arithmetic
and comparison branches are checked, and payable entries stay payable.

The event pass adds log effects to the classified storage effects.
It scans through temporary stores so a later log still makes an entry
nonpayable. Twenty checks cover the same ten entries with and without
an event declaration: simple and nested reads, guarded arithmetic,
scalar writes before and after a read, simple and nested mapping writes,
payable reads and writes, and a read with an optional log.

## Lean and erasure controls

[`verification/test/AbiControls.lean`](../verification/test/AbiControls.lean)
contains valid boundary witnesses and two refinement equalities. Both
equalities are proved by `rfl`: `refine .uint8 255` accepts with the
exact value 255, and `refine .uint8 256` rejects with
`.outOfRange .uint8`. Thus a change that makes `refine` accept 256 or
reject 255 stops the unchanged control. The gate
compiles the unchanged file, applies each of eight mutations separately,
then compiles the unchanged control again. Each mutant must fail with a
type error on the edited line:

| Mutant | Invalid witness |
| --- | --- |
| Uint8 | 256 |
| Uint256 | 2^256 |
| Address | 2^160 |
| Bool | 2 |
| Packed field | One byte at offset 32 |
| Storage slot | A function instead of a Word |
| Storage value | A function instead of a Word |
| Refinement rejection | The rejection of Uint8 value 256 replaced by a claim that `refine` accepts 256 with some refined value |

The gate also reruns the [storage proof](M2-STORAGE-PROOFS.md) axiom
oracle, its seven negative controls, the seven implementation mutants
(six compile rejections and one semantic rejection), and the thirteen
theorem erasure checks with their executable-symbol control. It does
not weaken the per-theorem axiom allowlist.

The expected marker is:

```text
M2-ABI entries=12 abi_controls=16 mutability=20 lean_negatives=8 storage_mutants=7 axiom_controls=7 erasure=13 jq_sorted=equal OK
```
